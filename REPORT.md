# Short Report — AI Agent Battle: Tic-Tac-Toe

## Objective and implementation
This project implements a Python Tic-Tac-Toe engine and two AI agents using Minimax with Alpha-Beta pruning. Search depth is configurable. The program counts evaluated nodes and pruned branches and saves experiment data to CSV.

## Agents
- **NEXUS:** depth 3; threat-focused heuristic H1, rewarding open two-in-a-row lines and penalizing opponent threats.
- **TITAN:** depth 3; positional heuristic H2, combining line threats with center and corner occupancy.
Both agents use the same search algorithm. Randomness is used only to break exact-score ties.

## Experiments and recorded results
Experiment 1 holds H1 and the algorithm constant and compares depths 1–4 over 20 alternating-start games per depth. Experiment 2 runs 10 NEXUS-versus-TITAN games, alternating the first player. The exact generated records are in `results/depth_experiment.csv` and `results/results.csv`.

## Analysis and conclusion
The depth experiment shows the computation cost of looking further ahead: node visits and runtime rise with depth in this run. Alpha-Beta pruning skips branches that cannot affect the Minimax decision. The depth experiment produced draws throughout, illustrating that deeper search does not necessarily change the final outcome in a solved, small game. NEXUS and TITAN differ in how they value positions, so compare their game results alongside node counts, pruning and time rather than declaring a universal winner from wins alone. Runtime varies by machine; rerun the commands before submission if you want locally measured timings.

## Reproduction
From the repository root, run `python main.py depth` and `python main.py battle`. Results are generated by the program and are not hard-coded.
